出海不是建一个软件
是在异国合法地长期经营

02 / 体系主体

五层结构：必须同时成立，不可跳层

出海不是七段式流程，而是五层必须同时成立的经营结构。任何一层塌了，整盘棋崩。点击展开每层。

03 / 核心矛盾

三个时钟：为什么出海注定别扭

这是软件项目完全没有的东西，也是出海项目失败的第一大原因——机会窗口通常短于建制周期。

核心冲突：窗口在关，牌照还在排队

市场空位可能只有 6 个月，但当地公司注册 + 行业牌照 + 税务架构 + 银行开户走完要 18~24 个月，而且法定周期不可压缩。如果你按"先建制、再卖货"的顺序走，等你拿到门票时窗口已经关了。

解法 01
由建制门槛倒推国别顺序

先用建制门槛低的模式和市场（出口、跨境电商，往往不需要本地实体和重牌照）抢窗口、验证模式、攒数据；等建制能力成熟，再去打重资产/严合规市场。

解法 02
并行而非串行

建制线和市场线同时跑。不要"先把公司注册好再开始卖"。注册走 A 律师，业务验证走另一条线，两套节奏互不阻塞。

解法 03
按模式匹配资源

轻模式（电商/出口）投小钱快验证；重模式（建厂/设实体）只在单位经济被证明为正之后才投。资源跟着模式走，不跟着想象走。

04 / 决策机制

七道关卡：不用"阶段"，用"关卡"

软件项目是「阶段评审→通过就往下走」。出海项目是关卡决策→通过 / 否决 / 缩范围 / 止损退出。每一道关卡都可能杀死整个项目。点击展开。

核心纪律：止损条件必须在进关前书面确认

否则沉没成本会绑架之后每一个决策。这是软件项目根本不需要、而出海项目必须有的机制。进关那一刻就把"什么情况下我们认输"写死，不许事后改口径、不许换算新指标美化。

05 / 风险管理

五类风险台账 + 风险雷达

台账必须持续更新，且每条风险都要有责任人 + 应对预案 + 触发信号（早期预警指标）——没有预警信号的风险台账只是摆设。

06 / 财务真相

单位经济：出海项目最容易自杀的地方

不合并看 P&L。亏损国长期被盈利国掩盖，是出海财务最经典的自欺。每个国家独立算，UE 不转正的缩规模。

最容易被漏掉的 20~30% 成本

注册维护费、年审、审计、律师、牌照续期、认证复审、商标续展。这些不进"到岸成本"，但持续吃利润。做 UE 时必须单列一行叫 "合规持有成本"，很多项目就是死在这一行。

07 / 权责机制

总部 vs 当地：内耗的根源

出海项目最常见的内耗来自一条结构性矛盾——当地有信息，总部有决策权。解法不是开会，是设计授权矩阵。

结构矛盾：当地有信息，总部有决策权 → 必然打架

中方的"先研究再决定" vs 本地的"先做了再说"。不要互相否定，要明确各自适用场景。

解法四件套：授权矩阵（金额/人事/合同/合规四类权限逐级下放）· 决策时效 SLA（慢一天丢单，快一天违规）· 上报红线（不报不算授权）· 冲突升级路径

08 / 方法论取舍

只借鉴这三样，其余全部丢掉

软件工程的方法论不是不能用，而是必须改造后用。原样照搬只会掩盖真正的问题。

09 / 一页纸总结
出海 = 战略选战场 × 建制换门票 × 经营算得清 × 市场打得进 × 组织留得住
三时钟打架 → 由建制门槛倒推国别顺序，机会与建制并行推进
七道关卡 → 每关可「通过 / 否决 / 缩范围 / 止损」，止损线进关前写死，事后不许改口径
两把尺子 → 关卡通过度 + 分国别运营健康指标，不用"项目完成度 80%"这种话
